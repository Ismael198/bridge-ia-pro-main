# Agent Customization Guide — bridge-ia-pro

Full-stack marketplace platform with TanStack Start (React SSR), Supabase, and Cloudflare Workers. Manages agents, chat, listings, orders, and marketplace integrations (Mercado Livre).

## Quick Start for Agents

### Build & Run
- **Dev**: `npm run dev` → Vite dev server on port 5173 with SSR
- **Build**: `npm run build` → TanStack Start SSR bundle for Cloudflare Workers
- **Preview**: `npm run preview` → Test production bundle locally
- **Lint**: `npm run lint` → ESLint validation
- **Format**: `npm run format` → Prettier auto-formatting
- **Deploy**: `wrangler deploy` → Deploy to Cloudflare Workers

### Architecture at a Glance

**Frontend/SSR** (`src/`)
- **Entry**: `src/start.ts` (TanStack Start client entry)
- **Routes**: File-based routing (`src/routes/*.tsx`)
  - `_authenticated.*.tsx` — Protected routes (require Supabase session)
  - `index.tsx`, `login.tsx`, `signup.tsx` — Public routes
  - `api/` — Server functions (run on CF Workers)
- **Components**: Radix UI + Tailwind CSS (`src/components/`)
- **Server**: `src/server.ts` — Custom SSR error wrapper for Cloudflare
- **Router**: TanStack Router with file-based code generation

**Backend/Database** (`supabase/`)
- PostgreSQL database via Supabase
- Auth: Supabase Auth (session-based, JWT tokens)
- Migrations: `supabase/migrations/` (schema versioning)
- Config: `supabase/config.toml` (local dev settings)

**Deployment** (`wrangler.jsonc`)
- Cloudflare Workers (Node.js compat enabled)
- SSR rendering on edge, static assets on CDN
- Environment: See `wrangler.jsonc` for secrets/KV setup

**Marketplace Integration** (`src/lib/`)
- `mercadolivre.server.ts` — Server-side Mercado Livre API calls
- `marketplaces.functions.ts` — Marketplace-related edge functions
- Supabase integration: `src/integrations/supabase/`

### Key Conventions & Patterns

| Pattern | Location | Notes |
|---------|----------|-------|
| **Routes** | `src/routes/` | File-based naming: `_authenticated.agents.tsx`, `api/fetch-data.ts`. Use `_authenticated.tsx` for layout. |
| **Server Functions** | `src/routes/api/*.ts` | Run on Cloudflare Workers edge; use `createServerFn()` from TanStack Start. Access headers, secrets, Supabase here. |
| **API Client** | `src/integrations/supabase/` | Supabase JS client for RLS-protected queries. Auth token auto-attached. |
| **Data Fetching** | React Query + Server Functions | Use `useQuery()` + `createServerFn()` for SSR + client revalidation. |
| **Authentication** | Supabase Auth | Session token in cookie (auto-managed). Check `AuthProvider.tsx` for session setup. |
| **Styling** | `src/styles.css` + Tailwind | Utility-first Tailwind + Radix UI. Use shadcn/ui patterns. |
| **TypeScript** | Strict mode | All `.ts`/`.tsx` files; generated router types in `routeTree.gen.ts` (auto-generated, don't edit). |
| **Environment** | `wrangler.jsonc` | Cloudflare secrets, KV bindings, triggers. Local dev uses `.env` (not committed). |

### Common Pitfalls for Agents

1. **SSR Context**: Server functions run on Cloudflare Workers (edge), not in Node.js. No `__dirname`, filesystem access, or long-running processes. Use Supabase for data, KV for caching.
2. **Supabase Auth**: Session token is in HTTP-only cookie. Client-side `useUser()` hook reads from React context set by `AuthProvider.tsx`. Always check `user?.id` before making auth-required calls.
3. **Generated Files**: `routeTree.gen.ts` is auto-generated by TanStack Router. Never edit it—changes will be overwritten. Declare routes by creating `.tsx` files.
4. **Environment Variables**: Use `wrangler.jsonc` for Cloudflare secrets (`[[env.production]]`). Local dev: `.env` (loaded by Vite).
5. **Mercado Livre Integration**: Requires server-side API calls. See `mercadolivre.server.ts`—cannot call from browser (CORS). Always proxy through server function.
6. **Cloudflare Workers Limits**: Max 50ms CPU time per request (timeout at 30s). Optimize queries, batch operations. Use Durable Objects if you need state persistence.

### When to Ask for Human Input

- **Supabase schema changes**: Altering tables, columns, RLS policies should be reviewed for data integrity
- **Mercado Livre API**: External API endpoints may change; check official docs before assuming behavior
- **Cloudflare secrets**: Adding new secrets (API keys, tokens) requires manual setup in CF dashboard
- **Production deployment**: Database migrations, secret rotations, or traffic redirects should be reviewed before applying
- **Authentication flows**: Changing Supabase Auth config (providers, token expiry, etc.) impacts all users
