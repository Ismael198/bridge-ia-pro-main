# Project Constitution: bridge-ia-pro

## 📌 Project Context & Overview
We are building a scalable, multi-tenant full-stack marketplace platform (`bridge-ia-pro`) connecting buyers, sellers, and external marketplaces. The core infrastructure relies on server-side rendering (SSR) at the edge, native database security via RLS, and secure proxying for third-party marketplace integrations (such as Mercado Livre).

## 🛠️ Tech Stack & Dependencies
- **Frontend & SSR:** React, TypeScript, TanStack Start (File-based routing & SSR)
- **Styling & UI:** Tailwind CSS, Radix UI (shadcn/ui patterns)
- **Database & Auth:** PostgreSQL via Supabase (Row Level Security & Session-based Auth)
- **Serverless/Edge:** Cloudflare Workers (Node.js compatibility mode enabled)
- **Integrations:** Mercado Livre Server-side API

## 📏 Coding Standards
1. **TypeScript First:** Strict mode enabled. Never use the `any` type. Explicitly type all Server Functions, API responses, and database schemas using types generated from the Supabase CLI.
2. **Component Architecture:** Keep UI components presentational and small. Separate business logic by leveraging React Query and TanStack Start's `createServerFn()`.
3. **Edge Context Limits:** Server functions run on Cloudflare Workers. **DO NOT** use native Node.js APIs (`fs`, `path`, etc.). Keep computations lean to respect the **50ms CPU time limit** per request.
4. **Marketplace Isolation:** All Mercado Livre API interactions must live in `src/lib/mercadolivre.server.ts`. Never trigger these calls from the browser due to CORS and security constraints; always proxy them through a Server Function.
5. **Database Security (RLS):** Every single table in the database must have Row Level Security enabled. Never query tables directly from the client without proper RLS policies enforced.

## 🚀 Workflow & Conventions
- **Commands & Local Dev:** 
  - Package Manager: `npm`
  - Dev Server: `npm run dev` (Vite on port 5173)
  - Local Database: `supabase start` to spin up local Postgres
  - Build Check: `npm run build` to compile the TanStack Start bundle for Cloudflare Workers
- **Generated Files:** Never manually edit `src/routes/routeTree.gen.ts`. It is auto-generated by TanStack Router. Declare routes strictly by creating `.tsx` files inside `src/routes/`.
- **Git Messages:** Follow the Conventional Commits format (e.g., `feat(auth): implement authenticated layout guard`, `fix(ml): patch access token rotation on edge`).

## 🚫 Explicit Constraints (DO NOTs)
- **DO NOT** hardcode secrets or credentials. Use `.env` for local development and `wrangler.jsonc` for production Cloudflare secrets.
- **DO NOT** bypass the routing layout guards. Protected routes requiring a valid Supabase session must inherit from `_authenticated.*.tsx`.
- **DO NOT** push migrations manually to production. All schema and RLS modifications must be versioned strictly inside `supabase/migrations/`.
- **DO NOT** make client-side requests to external marketplace endpoints.

## 🔗 Connected Tools & Project Context
- **Supabase CLI:** Used for local database shadowing, diffing, and type generation.
- **Wrangler CLI:** Used for previewing edge environment conditions locally and deploying to Cloudflare Workers.
- GitHub MCP for managing Pull Requests.
- Filesystem MCP for creating and modifying code securely.
- PostgreSQL MCP for direct, secure database schema prototyping.
